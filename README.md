# 生活管理小程序

> 把散落在六七个 App 里的日常记录，收进一个微信小程序。

微信小程序原生开发 + 微信云开发（CloudBase），**没有自建服务器**。所有数据按微信用户隔离存储在云端，换设备不丢失。

**为什么做这个**：日常要记的东西散落在习惯打卡、记账、健身、备忘录、经期、饮食六七个 App 里，每个都只想用其中一小部分，却要分别打开、分别登录。于是做了这个把它们收进同一个入口、共用一套身体数据的小程序。

---

## 功能模块

首页「今天」聚合当天最常看的信息，其余功能收在「功能」页，两处都支持自定义排序。

| 模块 | 能做什么 |
| --- | --- |
| 今天 | 首页聚合：习惯打卡、天气、黄历、热量计算、待办事项五张卡片，可展开、可排序 |
| 习惯打卡 | 自由增删习惯，支持「每天一次」「每周 N 次」两种频次；同时统计连续打卡天数与连续达标周数 |
| 记账 | 收支流水、月度结余汇总、九类分类 |
| 训练规划 | 内置 35 个动作、5 套计划模板；日历排课；训练中逐组记录重量与次数、组间休息倒计时、PR 墙 |
| 有氧训练 | 跑步 / 爬坡 / 爬楼机 / 骑行等 6 种，按 MET 公式估算消耗 |
| 食物热量 | 拍照上传 → 多模态模型识别食物 → 估算克数与热量 → 计入当日热量缺口 |
| 今天吃什么 | 日历规划每天吃什么，支持自定义菜谱库 |
| 灵感记录 | 仿 iPhone 备忘录：自动保存、左滑删除、搜索 |
| 日程安排 | 日历排期，到日期的待办自动出现在「今天」的待办列表 |
| 情绪日记 | 日历上以色点记录每天心情，支持自定义心情与配色 |
| 经期记录 | 周期预测、排卵日与易孕窗口、日历着色 |
| 我的 | 昵称头像与身体数据，用于计算 BMR / TDEE |

另有 4 个已完成、但因微信对占卜类内容审核较严而**临时隐藏入口**的模块：**八字排盘、六爻断卦、塔罗占卜、每日一签**。页面代码完整保留在仓库中，仅在 `pages/feature/feature.js` 里以 `AUDIT-HIDDEN` 注释标记入口位置。

## 技术栈

- 微信小程序原生（WXML / WXSS / JS），未引入第三方 UI 框架
- 微信云开发 CloudBase：云函数、云数据库、云存储
- 云函数运行时 Node.js（`wx-server-sdk`、`axios`）
- AI 能力：OpenAI 兼容接口（多模态识图 + 文本生成），可替换为国内同接口厂商
- **纯本地算法实现**（不依赖任何接口）：农历黄历、八字排盘、六爻纳甲、塔罗牌阵、经期预测、BMR/TDEE、MET 热量估算

## 关键设计决策

这一节是这个项目里最值得看的部分——每条都来自一个具体踩过的坑。

**1. 用云开发而不是自建后端。**
云开发数据库的默认权限是「仅创建者可读写」，配合云函数拿到的 `openid`，多用户隔离天然成立，不需要写一行鉴权代码，也省掉了服务器与备案。代价是绑定微信生态、数据不易迁出；对个人工具类产品，这个取舍是划算的。

**2. 天气接口从直连改为云函数代理。**
`wx.request` 受小程序「合法域名白名单」限制，`api.open-meteo.com` 不在白名单内会被直接拦截。改由云函数发起请求——云函数不受白名单约束——前端接口签名不变，只换实现。

**3. 城市检索从在线接口改为内置 300+ 城市库。**
在线地理编码服务对中国小城市覆盖很差，搜索经常返回空数组，还得再多配一个域名白名单。改为在 `utils/cities.js` 内置 300 多个城市，支持「精确匹配 → 前缀匹配 → 包含匹配」的三级优先级检索：零网络请求、零延迟、结果可控。

**4. 云函数超时从 3 秒调到 20 秒。**
涉及外网请求的云函数在网络抖动时会报 `-504003 FUNCTION_TIME_LIMIT_EXCEEDED`——微信云函数默认超时只有 3 秒。通过给云函数加 `config.json`，把超时提到同步调用的上限 20 秒。

**5. AI 输出不稳定时的兜底。**
多模态模型被要求「只返回 JSON」，但部分模型仍会夹带解释文字。代码用正则从响应中提取 JSON 块再解析；若解析失败或未配置 API Key，则返回带 `mock: true` 标记的演示数据——界面可以先跑通，前端也能明确告知用户当前是演示数据。

**6. 占卜类功能的审核风险处理。**
微信对占卜、算命类内容审核严格。这里没有选择硬上线赌一把，而是在功能列表中以注释形式保留入口并标记 `AUDIT-HIDDEN`，页面代码完整保留。既不挡过审，将来也不用重写。

**7. 规避小程序渲染层的兼容性限制。**
微信的 WXSS 编译器与 `{{ }}` 数据绑定的能力都弱于浏览器：不支持 `inset` 简写、不支持中文类选择器、`{{ }}` 内不能调用数组方法（`indexOf` / `includes`）。这些都在开发中逐个定位并改写——例如把布尔判断预先在工具模块里算好，模板只做属性访问。

## 本地运行

1. 注册微信小程序账号，拿到 AppID，填入 `project.config.json`
2. 微信开发者工具「导入项目」，选择本项目目录
3. 开通云开发，把环境 ID 填入 `utils/config.js` 的 `CLOUD_ENV`
4. 在云开发控制台创建下列 17 个集合，权限统一设为「仅创建者可读写」
5. 右键 `cloudfunctions/` 下的云函数 →「上传并部署：云端安装依赖」
6. 可选：给 `aiFood` 与 `aiTarot` 配置云函数环境变量 `AI_API_KEY` / `AI_API_URL` / `AI_MODEL`。不配置也能正常运行，接口会返回演示数据

## 数据模型

全部集合都以微信 `openid` 为隔离边界，用户之间互不可见。

| 集合 | 用途 |
| --- | --- |
| `habits` / `checkins` | 习惯定义 / 每日打卡记录 |
| `bills` | 收支流水 |

| `training_plans` / `training_schedule` / `training_logs` | 训练模板 / 排课 / 训练日志 |
| `food_log` | 食物识别记录 |
| `eat_plan` / `eat_custom` | 每日饮食规划 / 自定义菜谱 |
| `mood_logs` / `mood_types` | 情绪记录 / 自定义心情 |
| `period_logs` | 经期记录 |

| `bazi` / `liuyao` | 排盘与占卜历史（模块隐藏中） |

## 已知限制

- 订阅消息提醒尚未接入：`utils/config.js` 里 `REMINDER_TMPL_ID` 仍是占位符，`sendReminder` 云函数未挂定时触发器
- 没有自动化测试，验证方式是 `node --check` 加上针对算法的一次性校验脚本
- 八字排盘的节气计算使用通用寿星公式，个别年份的节气边界可能相差一天，页面已标注「仅供娱乐参考」
- 尚未接入行为数据埋点，因此没有留存、转化等运营指标
